# Summary of work on 2026-08-15

## Delivered pipeline foundation

- Built a typed, synchronous Python pipeline for Instagram recipe processing.
- Added adapters for best-effort Reel acquisition with `yt-dlp`, FFmpeg audio
  and frame extraction, Faster-Whisper transcription, PaddleOCR, deterministic
  OCR gating, recipe validation, and local JSON artifact caching.
- Implemented caption-first processing: validate a recipe from the acquired
  caption before falling back to audio/transcription and OCR.
- Added OpenAI structured recipe extraction as the practical fallback extractor.
  The prompt ignores emojis, macro/nutrition text, serving counts, and marketing
  content; validation and evidence grounding remain provider-independent.
- Added OpenAI usage metadata capture from the Responses API and a reusable
  reporting-layer cost calculator. Cached pipeline reruns preserve original
  usage metadata and make no additional API request.

## Google Sheets to Google Docs workflow

  - optionally moving the document into a Drive folder; and
  - appending the recipe title and Doc URL to the matching Recipe Master Doc tab.
- Implemented local publication checkpoints so a retry reuses an already-created
  Google Doc and does not duplicate the Master Sheet row.
- The real single-item Google vertical-slice smoke test completed successfully:

## Batch queue processing

- Expanded queue rows from two fields to four:

  ```text
  URL | Description | Status | Detail
  ```

- Added the visible statuses `Pending`, `Processing`, `Published`, `Review`,
  and `Error`. Blank status cells are treated as `Pending`.
- Added `GoogleSheetsRecipeQueueStateWriter` to update the status/detail cells
  for the correct category tab and row.
- Added `QueuedRecipeWorkflow.process_all(max_items=...)`, which processes
  eligible rows sequentially, remains synchronous, and continues after an
  individual failure.
- A successful item records `Published` and its Google Doc URL. An incomplete
  recipe records `Review` and its validation reason. An operational failure
  records `Error` and its message.
- `Published`, `Review`, and `Error` rows are skipped on future runs. An
  interrupted `Processing` row is eligible to resume; publication checkpoints
  still prevent duplicate delivery work.
- Added the real, paid/manual batch smoke script
  `tests/scripts/google_batch_smoke.py`. It requires explicit
  `--execute-writes`, defaults to two items, reruns the batch to prove terminal
  rows are skipped, and supports `--all` only after the bounded smoke succeeds.

  mode rather than processing additional Pending rows.

## Review delivery architecture

- Added a separate idempotent delivery path for `REVIEW` results: create/reuse a
  Review Doc, place it in the configured Review Drive folder, append one row to
  the matching category tab of the Review Sheet, and link the Review Doc from
  the original queue row.
- Review delivery has its own local checkpoint, so retries do not duplicate a
  Review Doc or Review Sheet row. Review items remain excluded from the Recipe
  Master Doc.
- The Review Sheet's human-managed status values are `Review`, `Accepted`, and
  `Rejected`.

## Review decision promotion

- Added the OOP foundation for a separately invoked manual-decision worker.
  It promotes `Accepted` Review Sheet rows into clean final Recipe Docs and the
  Recipe Master Doc, or moves `Rejected` Review Docs into a rejected folder and
  archives them in the rejected spreadsheet.
- Both paths save a resolution checkpoint before removing the active Review
  Sheet row, making retries safe. The rejected destinations are configured only
  in the untracked local Google workflow configuration.

## Repository hygiene

- OAuth client secrets, refresh tokens, API keys, downloaded media, generated
  artifacts, and smoke-test result files remain outside Git.
- Keep the local working directory and publication checkpoints available between
  runs so retries retain their idempotency guarantees.
