## Proposed pipeline

1. Read an Instagram Reel URL from the Google Sheet.

2. Acquire the source media.
   - Attempt an unauthenticated yt-dlp download for an authorized/public Reel.
   - Treat yt-dlp as an experimental, best-effort acquisition adapter.
   - Fall back to a manually supplied local file if downloading fails.
   - Extract the Reel shortcode from the URL.
   - Save yt-dlp metadata, including the caption and creator information.
   - Use FFprobe to validate video and audio streams, codecs, dimensions, and
     duration.
   - Calculate a SHA-256 content fingerprint for integrity and idempotency.
   - Write download metadata to a JSON artifact.

3. Transcribe the downloaded video.
   - Use faster-whisper locally on CPU with INT8 computation.
   - Preserve timestamped transcript segments.
   - Produce a transcript JSON artifact.
   - The existing transcription smoke test still needs CLI input, corrected
     timing, and JSON output.

4. Evaluate caption and transcript completeness.
   - Attempt preliminary structured recipe extraction.
   - Validate evidence coverage and required recipe information.
   - Skip OCR when the caption and transcript provide sufficient evidence.
   - Run OCR when the recipe is incomplete, conflicting, or refers to
     information displayed on screen.

5. Extract frames when OCR is required.
   - Probe the source using FFprobe.
   - Sample timestamped frames using FFmpeg.
   - Support an optional crop for screen recordings.
   - Clean downloaded Reels do not normally need cropping.
   - Write a frame manifest consumed by OCR.
   - Create a JPEG contact sheet for visual quality inspection.
   - Add perceptual deduplication before production OCR.

6. Run conditional OCR.
   - Use PaddleOCR 3.7.0 with the PaddlePaddle CPU runtime.
   - Keep oneDNN disabled because it currently fails in this environment.
   - Preserve text, confidence, bounding polygons, and timestamps.
   - Consolidate repeated or conflicting readings across adjacent frames.
   - OCR is currently the largest performance bottleneck.

7. Combine the caption, transcript, and optional OCR as separate evidence
   sources.
   - Preserve evidence references and confidence for every extracted claim.
   - Do not silently resolve conflicts or invent missing recipe information.
   - Classify incomplete or conflicting recipes as `REVIEW`, not operational
     errors.

8. Produce and validate a structured recipe, render it into a Google Docs
   template, and write the result and job state back to the Google Sheet.

## Smoke-test findings

- yt-dlp successfully downloaded public Reels without cookies.
- Downloaded media contained valid video and audio streams.
- yt-dlp metadata included the Instagram caption and creator information.
- faster-whisper worked locally on CPU.
- FFmpeg frame extraction and optional crop support worked.
- PaddleOCR recognized recipe ingredient overlays.
- OCR errors varied across adjacent frames, demonstrating the need for
  consensus logic.
- PaddleOCR's oneDNN execution path raised an internal error, while plain CPU
  inference succeeded.
- OCR on one full-resolution 1080x1920 frame took approximately 35 seconds,
  making OCR the largest measured bottleneck.
- Frame resizing, perceptual deduplication, representative-frame selection,
  and possibly a mobile OCR detector should be evaluated before production
  OCR.

  - Records a SHA-256 fingerprint and stage timing.
- `tests/scripts/fw_transcription_test.py`
  - Demonstrates local faster-whisper transcription.
  - Still needs to accept a CLI media path, measure the fully consumed
    transcript, and write structured JSON.
- `tests/scripts/frame_extraction_smoke.py`
  - Samples timestamped frames and writes a manifest.
  - Supports optional pixel-based cropping.
  - Produces a JPEG contact sheet and stage timing.
- `tests/scripts/ocr_smoke.py`
  - Consumes a frame manifest and runs PaddleOCR.
  - Preserves timestamps, text, confidence, and polygons.
  - Writes raw detections, repeated-text summaries, and timing statistics.
